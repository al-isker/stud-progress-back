# Корпус фикстур `test-document-parser`

Фикстуры для интеграционного теста модуля (`../parse-test-document.spec.ts`).

## Структура

Каждая папка в `fixtures/` — отдельный кейс:

    fixtures/
    └─ NNN/
       ├─ document.<ext>   # исходный документ
       ├─ expected.json    # ожидаемый полный ParseResult
       └─ README.md        # описание (заполняется вручную)

`expected.json` обязателен для каждого кейса. Он может содержать как успешный результат (`status: "ACCEPTED"`), так и отклонённый (`status: "REJECTED"`).

## Правила анализа фикстур

Документы читай только в «умном» режиме, экономящем токены:

1. Не читай файл напрямую, весь анализ — через маленькие одноразовые Node/ts-node скрипты.
2. Если в проекте уже есть код извлечения/парсинга (PDF-экстрактор, сегментатор и т.п.) — используй его, а не пиши разбор с нуля.
3. Скрипт должен печатать только агрегаты: количества, гистограммы, доли, булевы флаги по объектам (вопросам/записям/страницам) — не построчный дамп содержимого.
4. Сначала получи сводку по всему файлу/корпусу целиком (общие счётчики), и только затем точечно углубляйся в конкретные аномалии — по их номеру/индексу, печатая только эти несколько строк.
5. Если вывод скрипта всё равно большой — перенаправляй в файл в scratchpad и читай его через grep/срез (offset/limit), а не целиком.
6. Временные скрипты можно не чистить, если они в scratchpad; в код проекта их не добавляй.

## Интеграционный тест

Тест сам находит все кейсы внутри `fixtures/`, поэтому добавление нового кейса не требует правок кода. Для каждого кейса он сравнивает полный результат парсинга с `expected.json`.
